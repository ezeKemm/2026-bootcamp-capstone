# Architectural Decision Record #0003
## K3s for deployment and routing
2026-10-09

### Context
The CRM application needs a Kubernetes-based runtime for deploying the frontend and backend and routing traffic to them.

This project previously selected OpenShift. The team has since chosen K3s instead, so deployment documentation and infrastructure plans should use standard Kubernetes resources and K3s-compatible tooling.

### Options
1. K3s
2. OpenShift
3. Another Kubernetes distribution or managed Kubernetes service

#### Decision
Choose K3s as the Kubernetes distribution for deployment and application routing. It provides a lightweight Kubernetes environment suitable for this project while retaining standard Kubernetes resource models.

### Consequences
- Deployments should use Kubernetes resources such as Deployments, Services, Ingresses, ConfigMaps, and Secrets.
- The cluster must have an ingress controller configured to route traffic to the frontend and backend.
- The team is responsible for operating and updating the K3s cluster and configuring its networking, storage, secrets, and monitoring.
- OpenShift-specific resources and terminology, such as Routes, Projects, ImageStreams, and Security Context Constraints, should not be assumed unless deliberately added.
- Related architecture and infrastructure documentation must be updated to remove outdated OpenShift assumptions.
